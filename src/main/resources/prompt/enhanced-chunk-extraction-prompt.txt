=== EXTRACTION GUIDELINES ===

Extract BOTH technical AND business knowledge for new development, migration, and modernization:
- TECHNICAL: Components, APIs, data models, deployment resources, configurations
- BUSINESS: Roles, capabilities, policies, decisions, workflows, rules, metrics, terms
- RELATIONSHIPS: How entities connect and depend on each other

CRITICAL INSTRUCTIONS:
1. **Entity Linking**: When identifying entities (component, workflow, role, capability, term), check if it matches something from the "Known X in Document" lists above. If it does, use the EXACT same name for consistency.

2. **Domain Inheritance**: All extracted entities inherit the domain/subdomain from document context unless explicitly stated otherwise in the chunk.

3. **Context Alignment**: If the chunk mentions concepts aligning with overall architecture, patterns, or known entities, reference them explicitly and increase confidence scores.

4. **Relationship Formation**: When forming relationships, prefer linking to known entities from document context rather than creating new entities.

5. **Confidence Scoring**:
   - High (0.9-1.0): Entity clearly mentioned AND aligns with document context
   - Medium (0.7-0.89): Entity clearly mentioned but not in document context
   - Low (0.5-0.69): Entity implied or partially described

6. **Business Rationale**: Capture the WHY (business rationale) not just WHAT (technical details)

7. **Workflow Actor Extraction**:
   Extract actors from workflow steps in this order:

   1. Explicit mentions: Role names, job titles, team names, system components
   2. Infer from action verbs:
      - "approve/approval" → "[Role] Approver"
      - "review" → "[Role] Reviewer"
      - "validate" → "Validator" or "Data Steward"
      - "calculate/transform/process" → "System" or service name
   3. Use workflow owner as fallback if mentioned
   4. Format: Roles in title case, systems prefixed with "System:"

8. **Workflow Trigger Extraction**:
   Extract trigger with context:

   1. Event: Look for "when", "upon", "after", "triggered by"
   2. Type: Manual/Scheduled/Event-driven/API/Data-driven
   3. Initiator: Role, system, or external party
   4. Purpose: Extract from "to ensure", "in order to", or infer from outcome
   5. Format: "{event}. Type: {type}. Initiator: {who}. Purpose: {why}"

   Example: "Order submission. Type: API. Initiator: Customer. Purpose: Validate inventory"
